# CLAUDE.md — mujoco_env_creator

Context for Claude Code in the **environment generator** repo. This is the sibling of `namo_cpp`
(`../namo_cpp`) and `sage_learning`. It turns **empty rooms (templates)** into **complete blocked
scenes** (walls + obstacles + robot + goal) that the NAMO Region-Opening pipeline trains/evals on.

## What this repo does (one paragraph)
`generate_envs.py` reads a template XML (walls only), randomly drops 1–N movable box obstacles,
runs MuJoCo + a wavefront occupancy analysis to find connected free **regions** and their
**adjacency**, then samples a robot and a goal into two regions with clearance/separation
constraints (the *pair* mode places robot in region i, goal in region j — that's what makes one
obstacle block the only path). Writes `output_dir/<template>/run_NNNN/env_XXXX.xml`. Needs the
NAMO C++ bindings (`namo_rl`) importable for the wavefront — set `PYTHONPATH` to namo_cpp's
`build_python` + `python`.

## Templates (the input rooms) — only TWO families now
Templates are **walls only**; robot/goal/obstacles are placed at generation time. `num_objects.json`
in each family gives per-template `[min,max]` obstacle counts.

- **`templates/feb_car/` (422)** — small rectangular rooms (~0.5–0.9 m × ~0.82 m), 4 boundary +
  4 bent inner walls with carved **doorway gaps**. Generated by `template_generation_real.py` from
  real-floorplan layouts. Born at car scale. Obstacle budget `[1,4]`. Split into 3 buckets by one knob:
  - `straight0_pts2` (140): `straight_wall_fraction=0.0` — angled/organic walls
  - `straight50_pts2` (140): half the inner walls forced axis-aligned
  - `straight100_pts2` (142): all axis-aligned / rectilinear
  - Name decoding: `pts2` = `points_per_side=2` (each inner wall = 2 segments); `straightN` = `fraction×100`.
- **`templates/aug9_car_v3/` (10)** — square benchmark arenas ~0.70 m, `set1`/`set2`, `benchmark_1..5`.
  Denser obstacle budgets `[3,10]` scaled by arena area. Already at car scale.

## Scaling (why and how)
The physical car is fixed at **7 cm**; only the *workspace* shrinks so obstacles actually block the path.
- `feb_car` is generated directly at car scale — no rescale.
- `aug9_car_v3` = `archive/aug9_car` rescaled by `scripts/rescale_aug9_to_v3.py`. The committed v3 used
  **factor 0.3** (1.165 → 0.3495). Script default is 0.23; docstring mentions 0.21 — the *files* are 0.3.
  Rules: wall pos + long axis ×factor; **thickness floored at 0.010** (1 cm half-extent, not scaled);
  **height/Z untouched** (walls stay 0.08 m); **car geometry not scaled**.
- Legacy alt path: the **v2** pipeline fed the *large* `aug9_car` to `generate_envs.py --robot-scale 0.233`,
  doing the scale at generation time instead of pre-scaling the template. v3 abandoned this for pre-scaled templates.

## `generate_envs.py` parameters

**Core**
- `template_xml` (positional) — walls-only room. `--namo-config` (required) — sim config (pinned `..._skill15_car_1x.yaml`).
- `--num-envs`, `--output-dir`, `--num-workers`, `--start-seed`, `--run-id-offset` (lets parallel invocations
  share one output dir with disjoint `run_NNNN` ranges).

**Obstacle count & geometry**
- `--num-objects-range MIN MAX` / `--num-objects-json` (per-template `[min,max]`; JSON wins). Count sampled per env.
- `--object-size-range MIN MAX` — full side length; W and H drawn independently → square/rect mix emerges.
- `--object-half-height` — z half-size (car: 0.05 = 10 cm tall, matches primitive ref scene). `--goal-size` — goal sphere radius.

**Robot scale (`--robot-scale`, default 1.0)** — multiplies the *unset* distance defaults (object size, clearance,
min-goal-dist, goal size) by the factor. `0.233` = 7 cm car path: forces clearance/min-goal to 0, object_half_height
0.05, object range ×0.233. CLI-set knobs always win. **v3 templates are pre-scaled, so v3 runs use the default 1.0**
with explicit object params; only the legacy v2 path used `--robot-scale 0.233` on the large aug9 templates.

**Region-pair / hop selection (the "multi-hop" knobs)** — the generator finds connected free **regions**, builds a
region **adjacency graph**, then enumerates region *pairs* and puts robot in one, goal in the other. Which pairs:
- `--require-adjacent` (**default ON**) — only **1-hop** pairs (regions that directly touch). One obstacle blocks the
  single doorway = the canonical Region-Opening puzzle. Disable via `--no-require-adjacent` (any pair in the component).
- `--exact-hop N` — only pairs whose **BFS distance in the region graph == N**. `1` ≡ require-adjacent; `2` = robot and
  goal separated by one intermediate region (must clear **two** doorways). Overrides `--require-adjacent`. Default 0 (off).
- `--samples-per-pair K` (default 1) — distinct (robot,goal) samples per (region-pair, ordering). 1 → up to 2 envs/pair
  (both orderings); raise to harvest many positions per pair.
- `--min-region-area M2` (default 0.02 ≈ 14×14 cm, 4× car footprint) — regions smaller than this are ineligible as
  robot/goal spots (still shown in the snapshot). Larger (0.05) forces "real-room" regions but causes more layout retries.

**Placement constraints** — `--clearance-radius`, `--min-goal-distance`, `--max-goal-retries`, `--require-adjacent`/
`--no-require-adjacent`. (Under `--robot-scale ≠ 1`, clearance + min-goal-distance auto-zero — region-pair semantics,
not Euclidean distance, define a valid problem.)

> **multi-hop ≠ multi-push.** `--exact-hop 2` = two *regions/doorways* to traverse (possibly different objects). The
> project's "multi-push" frontier is many pushes on **one** object to open **one** adjacent (1-hop) region. **All v3
> data is 1-hop** (require-adjacent default, no exact-hop) — multi-push lives *inside* 1-hop scenes.

## Key files
- `generate_envs.py` — main driver (single / pair / parallel-batch generation).
- `wavefront_snapshot.py` — occupancy grids (−2 occupied, −1 free), `region_map`, `adjacency`, cell-center sampling.
- `template_generation_real.py` (+ `_real_config.yaml`) — makes `feb_car` real-floorplan templates.
- `template_generation.py` — random-maze templates (older, not the v3 source).
- `placement_strategies.py` — robot/goal placement helpers.
- `scripts/rescale_aug9_to_v3.py` — aug9 large → v3 small.
- `scripts/inspect_snapshot.py`, `scripts/render_env_topdown.py` — debug/visualize.

## Gotchas
- A scene is keyed by **(pushed object, goal region)**, not by room XML — one room yields many episodes.
  Disjointness for train/test must be proven by **room geometry**, never file names (see namo_cpp side).
- Two wavefront exporter copies exist historically; ensure the intended one is on `PYTHONPATH`.
- Rasterisation tests the **cell center** (aligns with sampling) — robot/goal shouldn't land inside geometry.
